# BOTRD Web – ระบบเตรียมไฟล์นำเข้า RD Prep

เว็บสำหรับทีมบัญชี ใช้เตรียมข้อมูลใบแนบ ภ.ง.ด.1 / 2 / 3 / 53 / 54 แล้วดาวน์โหลดเป็นไฟล์ `.txt` ไปนำเข้าโปรแกรม **RD Prep** ของกรมสรรพากร

- ใช้พร้อมกันได้หลายคน หลายเครื่อง ทำงานบนคลาวด์ตลอดเวลา แม้ปิดคอมพิวเตอร์ของคุณ
- ล็อกอินด้วย Google เฉพาะอีเมลที่แอดมินเพิ่มไว้
- รองรับหลายบริษัท และแบ่งสิทธิ์ **แอดมิน / ผู้คีย์ / ผู้ตรวจ**
- ตรวจข้อมูลอัตโนมัติ และบันทึกประวัติทุกการแก้ไข
- ใช้บริการฟรีทั้งหมด: GitHub, Vercel (Hobby), Neon (Free) และ Google Sign-In

> ⚠️ **ข้อควรทราบเรื่องค่าใช้จ่ายและเงื่อนไข**
> - Vercel แพ็กเกจ Hobby (ฟรี) กำหนดให้ใช้งานส่วนตัวหรือไม่เชิงพาณิชย์ ถ้าใช้ในสำนักงานบัญชีที่มีรายได้ อาจขัดเงื่อนไขของ Vercel ควรอ่านเงื่อนไขล่าสุดของ Vercel และตัดสินใจเอง
> - ถ้าต้องการฟรีและใช้เชิงพาณิชย์ได้ ย้ายไปใช้ Cloudflare Pages หรือ Netlify ได้ภายหลัง
> - Neon Free มีพื้นที่ประมาณ 0.5 GB เก็บรายการได้หลายแสนแถว ถ้าไม่มีคนใช้ ฐานข้อมูลจะหยุดพัก การเปิดครั้งแรกหลังพักจึงช้าลงราว 1–2 วินาที

## 1. วิธีใช้งาน (สำหรับทีม)

| บทบาท | ทำอะไรได้ |
|---|---|
| **แอดมิน** | ทำได้ทุกอย่าง: เพิ่มบริษัท เพิ่มผู้ใช้ กำหนดว่าใครเห็นบริษัทไหน เปิดแก้ไขชุดที่อนุมัติแล้ว และลบชุดข้อมูล |
| **ผู้คีย์** | สร้างชุดข้อมูล นำเข้า Excel แก้ไขรายการ และส่งตรวจ |
| **ผู้ตรวจ** | ดูข้อมูล อนุมัติหรือตีกลับ และดาวน์โหลดไฟล์ .txt (อนุมัติงานที่ตัวเองเป็นคนส่งตรวจไม่ได้) |

**ขั้นตอนประจำเดือน**
1. **ผู้คีย์** เลือกบริษัท → สร้างชุดใหม่ โดยเลือกแบบ (เช่น ภ.ง.ด.53), งวด และครั้งที่ยื่น (ปกติ หรือยื่นเพิ่มเติม)
2. กด **ดาวน์โหลดแม่แบบ Excel** กรอกข้อมูล หรือวางจาก Express แบบ *Paste Values* แล้วกด **นำเข้า**
   - ระบบรู้จักชื่อหัวคอลัมน์ที่เขียนต่างกันได้บางแบบ เช่น "เลขผู้เสียภาษี", "วันที่จ่าย", "ภาษี"
   - เลือกได้ว่าจะ "เพิ่มต่อท้าย" หรือ "แทนที่ทั้งหมด"
   - แก้ไขในตารางบนเว็บได้ทันที ระบบบันทึกเองเมื่อออกจากช่อง
3. ดูแท็บ **จุดต้องสงสัย** แล้วแก้ ERROR ให้หมด ส่วน WARN และ INFO ให้พิจารณาทีละรายการ จากนั้นกด **ส่งตรวจ**
4. **ผู้ตรวจ** เทียบยอดรวม (เงินได้และภาษี) กับ Express แล้วกด **อนุมัติ** หรือ **ตีกลับ** พร้อมระบุเหตุผล
5. หลังอนุมัติแล้ว กด **ดาวน์โหลด .txt**
6. นำเข้าใน **RD Prep**
   1. เลือกแบบ → โอนย้ายข้อมูล → เลือกไฟล์ .txt
   2. ตัวคั่นเลือก **|**
   3. เปิดตัวเลือก **"บรรทัดแรกชื่อคอลัมน์"**
   4. จับคู่คอลัมน์ ชื่อคอลัมน์ในไฟล์ตั้งให้ตรงกับช่องใน RD Prep ไว้แล้ว
   5. รูปแบบวันที่เลือก **พ.ศ. dd/mm/yyyy**
   6. ถ้าภาษาไทยเพี้ยน ให้กลับไปดาวน์โหลดด้วยปุ่ม **.txt (TIS-620)** แทน

**สิ่งที่ระบบตรวจให้**
- **ERROR (ต้องแก้ ถึงจะส่งตรวจ อนุมัติ หรือดาวน์โหลดได้):** เลขผู้เสียภาษีผิด check digit, ภาษีไม่เท่ากับเงินได้ × อัตรา (กรณีเงื่อนไข 1), วันที่นอกงวด, ยอดเงินเกิน 2 ตำแหน่ง, เงื่อนไขไม่ใช่ 1/2/3, สาขาไม่ถูกต้อง, ข้อมูลที่บังคับกรอกไม่ครบ
- **WARN:** รายการที่อาจซ้ำ, จ่ายผู้รับเดียวกัน 3 ครั้งขึ้นไปในวันเดียว, ยอดสูงกว่า 5 เท่าของค่าเฉลี่ย, อัตราภาษีไม่ใช่อัตราปกติ, ใส่เลขนิติบุคคลใน ภ.ง.ด.3 (หรือกลับกัน)
- **INFO:** จ่ายในวันเสาร์หรืออาทิตย์, ยอดเงินกลม
- ระบบ**ไม่ปัดเศษ และไม่แก้ยอดเงินให้เอง** ทุกการแก้ไขดูได้ในแท็บ **ประวัติ**
- ถ้ามีคนสองคนแก้แถวเดียวกันพร้อมกัน ระบบจะไม่เขียนทับกัน คนที่บันทึกทีหลังจะได้ข้อความให้โหลดหน้าใหม่

> ภ.ง.ด.2 และ ภ.ง.ด.54 ยังไม่ได้ทดสอบนำเข้า RD Prep จริง ให้ทดลองนำเข้าก่อนใช้งาน

## 2. ติดตั้งครั้งแรก (ทำครั้งเดียว ประมาณ 20 นาที)

ต้องมีบัญชี 4 อย่าง: GitHub, Vercel, Neon และ Google ทุกบริการใช้แพ็กเกจฟรี

### ขั้นที่ 1 – GitHub: สร้าง repo และอัปโหลดโค้ด

1. ไปที่ https://github.com/new
   - **Repository name:** `botrd-web`
   - เลือก **Private**
   - **ไม่ต้อง**ติ๊ก Add a README (repo ต้องว่าง)
   - กด **Create repository**
2. อัปโหลดโค้ดได้ 2 ทาง เลือกทางใดทางหนึ่ง

   **ทาง ก – ให้ Claude push ให้**
   1. ไปที่ https://github.com/settings/personal-access-tokens/new
   2. **Token name:** `botrd-claude` · **Expiration:** 7 days
   3. **Repository access:** *Only select repositories* → เลือก `botrd-web`
   4. **Permissions → Repository permissions → Contents:** เลือก **Read and write** (Metadata จะได้สิทธิ์ Read ให้อัตโนมัติ)
   5. กด **Generate token** แล้วคัดลอก token ที่ขึ้นต้นด้วย `github_pat_…` ส่งให้ Claude พร้อมชื่อ user GitHub
   6. push เสร็จแล้ว ให้กลับไปหน้าเดิมแล้วกด **Delete** token ทิ้ง

   **ทาง ข – push เองจาก VS Code** (ต้องติดตั้ง Git ก่อน จาก https://git-scm.com)
   1. เปิดโฟลเดอร์ `D:\BOTRD\web` ใน VS Code
   2. กด <kbd>Ctrl</kbd>+<kbd>`</kbd> เพื่อเปิด Terminal แล้วพิมพ์ (แทน `YOUR_USER` ด้วยชื่อ user GitHub ของคุณ)
      ```bash
      git init
      git add .
      git commit -m "BOTRD web"
      git branch -M main
      git remote add origin https://github.com/YOUR_USER/botrd-web.git
      git push -u origin main
      ```
   3. ถ้ามีหน้าต่างให้ล็อกอิน GitHub ให้ล็อกอินตามขั้นตอน

### ขั้นที่ 2 – Neon: สร้างฐานข้อมูล

1. ไปที่ https://console.neon.tech → **New Project**
   - **Name:** `botrd`
   - **Region:** **AWS Asia Pacific (Singapore)** เลือก region นี้เพื่อให้อยู่ใกล้ Vercel
   - กด **Create**
2. ในหน้าโปรเจกต์ กด **Connect**
   - เปิดตัวเลือก **Connection pooling**
   - คัดลอก connection string ที่ขึ้นต้นด้วย `postgresql://` และลงท้ายด้วย `?sslmode=require`
   - เก็บค่านี้ไว้ใช้ในขั้นที่ 4 **ห้ามส่งให้ใครหรือแปะในแชท**
3. ไม่ต้องสร้างตารางเอง ระบบจะสร้างให้อัตโนมัติเมื่อเปิดเว็บครั้งแรก

### ขั้นที่ 3 – Google: สร้าง OAuth Client ID สำหรับปุ่ม "Sign in with Google"

1. ไปที่ https://console.cloud.google.com → เลือกโปรเจกต์ที่มุมบนซ้าย → **New Project**
   - **Project name:** `botrd`
   - กด **Create** แล้วเลือกโปรเจกต์นั้น
2. เมนู ☰ → **APIs & Services** → **OAuth consent screen** (บางบัญชีจะเห็นชื่อเมนูเป็น **Google Auth Platform**) → **Get started**
   - **App name:** `BOTRD`
   - **User support email:** อีเมลของคุณ
   - **Audience:** **External**
   - **Contact email:** อีเมลของคุณ
   - ติ๊กยอมรับเงื่อนไข แล้วกด **Create**
3. เปิดเมนู **Audience** ทำอย่างใดอย่างหนึ่ง
   - กด **Publish app** เพื่อให้ทุกอีเมลที่แอดมินเพิ่มในระบบล็อกอินได้ ระบบขอแค่อีเมลและชื่อ จึงไม่ต้องให้ Google ตรวจสอบแอป
   - หรือคงสถานะ *Testing* ไว้ แล้วเพิ่มอีเมลของทุกคนในทีมใน **Test users** (สูงสุด 100 คน)
4. เปิดเมนู **Clients** → **Create client**
   - **Application type:** **Web application**
   - **Name:** `BOTRD web`
   - **Authorized JavaScript origins** → **Add URI** → ใส่ URL ของเว็บจาก Vercel เช่น `https://botrd-web.vercel.app`
     - ถ้ายังไม่รู้ URL ให้ข้ามไปก่อน แล้วค่อยกลับมาเพิ่มหลังขั้นที่ 4
     - ต้องเป็น https และ**ไม่มี / ปิดท้าย**
   - **Authorized redirect URIs:** ไม่ต้องใส่
   - กด **Create**
5. คัดลอก **Client ID** ที่ลงท้ายด้วย `.apps.googleusercontent.com` ใช้แค่ค่านี้ ไม่ต้องใช้ Client secret

### ขั้นที่ 4 – Vercel: นำเว็บขึ้นออนไลน์

1. ไปที่ https://vercel.com/new → **Import Git Repository**
   - ถ้ายังไม่เคยเชื่อม GitHub: กด **Install / Configure GitHub App** → เลือก *Only select repositories* → `botrd-web` → **Install**
   - กด **Import** ที่ `botrd-web`
2. หน้าตั้งค่าโปรเจกต์
   - **Framework Preset:** **Other**
   - Build Command และ Output Directory ไม่ต้องแก้ ค่าตั้งไว้ใน `vercel.json` แล้ว
3. เปิดหัวข้อ **Environment Variables** แล้วเพิ่มค่าต่อไปนี้ทีละตัว

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | connection string จาก Neon (ขั้นที่ 2) |
   | `GOOGLE_CLIENT_ID` | Client ID จาก Google (ขั้นที่ 3) |
   | `SESSION_SECRET` | ข้อความสุ่มยาว ๆ ดูวิธีสร้างด้านล่าง |
   | `ADMIN_EMAILS` | อีเมล Google ของแอดมินคนแรก ถ้ามีหลายคนให้คั่นด้วย `,` |

   **วิธีสร้าง `SESSION_SECRET`:** เปิด Terminal ใน VS Code แล้วพิมพ์คำสั่งด้านล่าง จากนั้นคัดลอกผลลัพธ์ที่ได้
   ```bash
   node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
   ```
4. กด **Deploy** รอประมาณ 1 นาที จะได้ URL เช่น `https://botrd-web.vercel.app`
5. กลับไปที่ Google ขั้นที่ 3 ข้อ 4 แล้วใส่ URL นี้ใน **Authorized JavaScript origins**
   - Google อาจใช้เวลาไม่กี่นาทีถึงมีผล
6. ถ้าแก้ Environment Variables ภายหลัง ต้องไปที่ Vercel → **Deployments** → จุดสามจุด (⋯) ที่ deployment ล่าสุด → **Redeploy** ค่าใหม่จึงจะมีผล

### ขั้นที่ 5 – เริ่มใช้งาน
1. เปิด URL ของเว็บ → ล็อกอินด้วยอีเมลที่ใส่ไว้ใน `ADMIN_EMAILS` ระบบจะสร้างบัญชีแอดมินให้อัตโนมัติ
2. ไปที่เมนู **จัดการผู้ใช้/บริษัท**
   - เพิ่มบริษัทลูกค้า
   - เพิ่มอีเมลของทีม และเลือกบทบาท
   - ติ๊กเลือกบริษัทที่แต่ละคนเข้าถึงได้
3. ส่ง URL ให้ทีม แต่ละคนล็อกอินด้วยบัญชี Google ของอีเมลที่เพิ่มไว้

## 3. แก้ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| ปุ่ม Google ไม่ขึ้น หรือขึ้นข้อความ "origin_mismatch" | URL ใน Authorized JavaScript origins ต้องตรงกับ URL ของเว็บทุกตัวอักษร ต้องเป็น https และไม่มี / ปิดท้าย |
| ขึ้นข้อความ "อีเมลนี้ยังไม่ได้รับสิทธิ์" | ให้แอดมินเพิ่มอีเมลนั้นในหน้าผู้ใช้ |
| ขึ้นข้อความ "ยังไม่ได้ตั้งค่า DATABASE_URL / SESSION_SECRET" | เพิ่มค่านั้นใน Vercel Environment Variables แล้วกด Redeploy |
| ภาษาไทยใน RD Prep เพี้ยน | ดาวน์โหลดด้วยปุ่ม **.txt (TIS-620)** แทน |
| เปิดเว็บครั้งแรกของวันช้า | เป็นปกติของ Neon Free ที่ฐานข้อมูลตื่นจากการพัก ใช้เวลาประมาณ 1–2 วินาที |

## 4. สำหรับนักพัฒนา

```
api/index.js       API ทั้งหมด (Vercel Function เดียว)
lib/db.js          เชื่อม Neon และสร้างตารางอัตโนมัติ
lib/auth.js        ตรวจ Google ID token และ session cookie
public/rules.js    กฎของแต่ละแบบ การตรวจสอบ และการสร้างไฟล์ .txt (ใช้ร่วมกันทั้ง server และ browser)
public/app.js      หน้าเว็บ (JavaScript ล้วน ไม่มีขั้นตอน build)
tests/run.js       ชุดทดสอบ (ต้องมี Postgres ในเครื่อง)
tests/dev.js       เซิร์ฟเวอร์สำหรับทดสอบในเครื่อง
```

- **เพิ่มหรือแก้คอลัมน์ของแบบ:** แก้ `FORMS` ใน `public/rules.js`
- **เพิ่มชื่อหัวคอลัมน์ที่เขียนต่างกัน (เช่น จาก Express):** แก้ `ALIASES` ในไฟล์เดียวกัน
- **push ขึ้น GitHub แล้ว Vercel จะ deploy ให้อัตโนมัติ**
- **ความปลอดภัย**
  - ทุก API ต้องมี session ที่ลงลายเซ็นด้วย HMAC
  - คำขอที่เปลี่ยนแปลงข้อมูลต้องมี header กัน CSRF
  - ทุก SQL ส่งค่าผ่าน parameter
  - ผู้ใช้ที่ไม่ใช่แอดมินเห็นเฉพาะบริษัทที่ได้รับสิทธิ์
